# Feature Specification: 수집 자료의 근거 검증과 지식 구조화

**Feature Branch**: 미생성 — 브랜치 생성 훅이 설정되어 있지 않음

**Feature Directory**: `specs/001-source-knowledge-validation`

**Created**: 2026-09-07

**Updated**: 2026-09-07 — PM 관측 패키지의 입력·근거 재검증 한계 반영. 기능 목적과 MVP 범위는 유지.

**Status**: 초안(Draft)

**Constitution**: [프로젝트 헌법](../../.specify/memory/constitution.md) 1.0.0

**Input**: 사용자 요청: “W2가 제공한 수집 자료를 W3가 검토·구조화하여 W4가 출처와 제한을 확인하며 사용할 수 있는 Claim·명시 Requirement·근거 연결을 제공한다.”

이 기능은 수집 결과와 근거의 충분성을 구분하고, 원문이 부족한 자료가 검증된 사실처럼 전달되는 것을 막는다.
직접 사용자는 W2 수집 담당자, W3 지식 구조화 담당자, W4 추천 담당자다.
구직자는 이후 추천 단계에서 추적 가능한 기업 근거를 제공받는 간접 수혜자다.
별도 화면·수집기·검색기·추천 시스템은 이 기능의 요구가 아니다.

이 명세에서 **검증된 Claim**은 보존된 원문·버전·근거 위치와 진술의 의미·범위가 대조되고,
필요한 검증이 완료된 구조화 진술을 뜻한다.
기업의 주장을 독립적인 객관 사실로 인증하거나, 계획이 실제로 이행되었음을 보장하는 뜻이 아니다.
진술 검증 상태, 자료의 완전성, 접근·보존·활용 허용 상태는 각각 구분한다.
검증 결과가 있더라도 필요한 허용 확인이 끝나지 않은 내용은 공용 추천 근거로 전달하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입력의 누락과 보완 범위 확인 (Priority: P1)

수집 담당자는 자신이 전달한 자료의 어떤 부분이 구조화 가능한지,
무엇이 누락되어 보완이 필요한지 자료와 근거 구간별로 확인한다.

**Why this priority**: 수집 성공 표시만으로 불완전한 내용이 사실 근거로 전달되는 것을 처음부터 막는다.

**Independent Test**: 원문이 충분한 합성 입력, 기존 요약 전용 샘플, 새 PM 관측 패키지, 실패·누락 입력을 각각 제시하고
구조화 결과 생성 여부와 무관하게 자료별 검토 결과 및 보완 항목을 확인한다.

**Acceptance Scenarios**:

1. **AS-101** — **Given** 원문 발췌·출처 버전·근거 위치·무결성 확인 정보와 필요한 허용 상태가 있는 합성 자료,
   **When** 입력을 검토하면, **Then** 구조화 가능한 범위와 확인된 입력 정보를 식별할 수 있다.
2. **AS-102** — **Given** 기존 요약 전용 계약 샘플처럼 원문 발췌·출처 버전·해시 확인이 부족한 입력,
   **When** 입력을 검토하면, **Then** 각 누락을 보완 항목으로 전달하고 요약을 원문으로 취급하지 않으며
   검증된 Claim이나 검증된 채용 요구를 생성하지 않는다.
3. **AS-103** — **Given** 원문은 있으나 해당 출처 버전 또는 근거 위치를 확인할 수 없는 입력,
   **When** 검토하면, **Then** 참조가 부족하거나 잘못된 구간을 특정하고 그 구간의 검증 완료를 표시하지 않는다.
4. **AS-104** — **Given** 나머지 정보는 충분하지만 해시가 미계산이거나 제공된 무결성 정보가 본문과 맞지 않는 자료,
   **When** 검토하면, **Then** 무결성 확인 미완료 또는 불일치를 구분하고 해당 자료의 검증 완료를 표시하지 않는다.
5. **AS-105** — **Given** 성공 자료, 수집 실패 자료, 미파싱 첨부가 함께 전달된 입력,
   **When** 검토하면, **Then** 각각의 결과와 영향 범위가 남고 한 자료의 실패가 다른 자료의 결과를 숨기지 않는다.
6. **AS-106** — **Given** 개인·비공개 자료이거나 공용 활용·보존 허용 여부가 확인되지 않은 입력,
   **When** 검토하면, **Then** 해당 내용을 공용 지식으로 전달하지 않고 확인할 허용 범위와 제한 사유를 반환한다.
7. **AS-107** — **Given** 새 PM 패키지처럼 본문·첨부의 출처 버전, 실제 발췌, 부모 관계, 수집 측 검증 기록이 제공된 입력,
   **When** 검토하면, **Then** 제공된 ID와 근거를 유지하고 실제 누락·의도적 미보존·재검증 불가를 구분한다.
   기존 요약 샘플의 원문·버전 부재 진단을 일괄 적용하거나 수집 측 검증 표시로 W3 검증을 완료하지 않는다.
8. **AS-108** — **Given** 추출 성공이지만 선택 발췌만 보존된 본문과 다운로드 성공·텍스트 미확보 첨부,
   **When** 검토하면, **Then** 성공의 대상 범위와 첨부별 실제 상태를 유지한다.
   원격 HTTP 상태 기록의 부재를 다운로드 실패로 바꾸거나 자료 전체의 의미 분석이 완료됐다고 표시하지 않는다.

### User Story 2 - 원문까지 추적 가능한 Claim 확인 (Priority: P1)

지식 구조화 담당자는 원문이 충분한 자료에서 무엇이 실제로 언급되었는지 확인하고,
각 진술이 어느 자료의 어느 시점·구간을 근거로 하는지 추적한다.

**Why this priority**: 출처 연결과 진술의 정확한 범위를 보존하는 것이 이후 추천의 근거가 된다.

**Independent Test**: 허용 상태와 근거가 갖춰진 합성 원문 및 사전에 명시한 기대 진술을 사용하여,
수집·검색·추천 기능 없이 구조화 결과와 원문 대조를 검증한다.

**Acceptance Scenarios**:

1. **AS-201** — **Given** 합성 원문에 특정 조직이 특정 기간에 실행할 계획이 명시되어 있고 필요한 검증이 완료되는 조건,
   **When** 구조화하면, **Then** 계획 유형·대상·기간을 보존한 Claim을 제공하고 근거 구간과 출처 버전을 찾을 수 있다.
   계획을 관찰된 실행이나 완료 성과로 바꾸지 않는다.
2. **AS-202** — **Given** 원문에는 계획만 있고 성과 수치·사용 기술·채용 조건이 없는 자료,
   **When** 구조화하면, **Then** 없는 수치·기술·조건·성과를 생성하지 않는다.
3. **AS-203** — **Given** 원 URL은 접근할 수 없지만 허용 범위의 발췌·위치·당시 버전은 확인 가능한 자료,
   **When** 근거를 확인하면, **Then** 보존된 범위의 원문과 현재 접근 불가 상태를 확인할 수 있고 보존하지 않은 전문은 제공하지 않는다.
4. **AS-204** — **Given** 인용한 구간이 진술을 뒷받침하지 않거나 다른 버전의 구간을 가리키는 구조화 결과,
   **When** 검증하면, **Then** 해당 진술은 검증된 근거로 전달되지 않고 불일치 사유가 남는다.
5. **AS-205** — **Given** 원문 대조는 가능하지만 중요한 정보에 필요한 추가 검증이 아직 끝나지 않은 결과,
   **When** 전달 결과를 구성하면, **Then** 완료된 검사와 남은 검증을 구분하고 해당 진술을 검증 완료·활용 가능으로 표시하지 않는다.
6. **AS-206** — **Given** 원문 자료와 기존 SourceVersion 참조,
   **When** 구조화 결과를 생성하면, **Then** 입력 원문과 기존 버전 참조를 변경하지 않고 결과가 사용한 버전을 식별할 수 있다.
7. **AS-207** — **Given** 보존 발췌가 원문 노드·페이지·문단 안의 위치를 참조하지만 그 위치의 기준 텍스트는 현재 입력에 없는 경우,
   **When** 근거를 매핑하면, **Then** 발췌 안의 위치와 원문 위치를 구분하고 원래 근거 ID·버전을 유지한다.
   발췌 문자열의 대조 성공을 원래 위치의 재검증 성공으로 표시하지 않는다.
8. **AS-208** — **Given** 전체 자료·추출 전문의 해시와 과거 검증 표시가 있으나 해당 해시 대상은 현재 입력만으로 재현할 수 없는 경우,
   **When** 검증하면, **Then** 제공된 검증 주장과 이번에 재현한 검사를 구분한다.
   새로 계산한 발췌 해시로 원래 해시 대상을 대체하지 않고 필요한 검증이 미완료인 결과는 보류한다.

### User Story 3 - 명시 요구의 의미와 결합조건 확인 (Priority: P1)

지식 구조화 담당자와 추천 담당자는 공고의 실제 요구가 무엇인지,
필수·우대·일반 중 무엇인지, 어떤 조건을 함께 충족해야 하는지 확인한다.

**Why this priority**: 원문 조건의 변형은 이후 추천에서 필수요건 오표시와 경험 합성으로 이어질 수 있다.

**Independent Test**: 별도로 표시한 합성 공고 구간과 기대 조건을 제시하여,
개인 경험 매칭 없이 요구의 원문·범위·결합관계만 대조한다.

**Acceptance Scenarios**:

1. **AS-301** — **Given** 합성 공고에 “AWS 또는 GCP를 사용한 서비스의 운영 경험 필수”가 명시된 경우,
   **When** 구조화하면, **Then** AWS/GCP의 OR, 클라우드 사용과 운영의 결합,
   같은 서비스 운영 경험을 요구하는 의미 및 필수 구분을 보존한다.
   AWS와 GCP를 같은 기술로 합치거나 서로 다른 활동으로 충족했다고 판정하지 않는다.
2. **AS-302** — **Given** 일부 항목에는 우대가 명시되고 다른 항목에는 필수성 표시가 없는 합성 원문,
   **When** 구조화하면, **Then** 명시된 우대는 유지하고 불명확한 항목은 일반 요구로 둔다.
3. **AS-303** — **Given** 합성 자료에 “Amazon Web Services(AWS)”와 별개의 “Java”, “JavaScript”가 등장하는 경우,
   **When** 기술 표현을 정리하면, **Then** 원문 표현을 남기고 명확한 동의어만 연결하며 서로 다른 기술을 병합하지 않는다.
4. **AS-304** — **Given** 특정 조직·직무·공고에만 적용되는 명시 요구,
   **When** 구조화하면, **Then** 그 적용 범위를 보존하고 기업 전체나 다른 공고의 요구로 확대하지 않는다.
5. **AS-305** — **Given** 본문 원문은 충분하지만 상세 직무 설명은 미파싱 필수 첨부에만 있다는 입력,
   **When** 요구를 구조화하면, **Then** 본문이 직접 뒷받침하는 요구만 제공하고 첨부의 세부 요구는 미확인으로 남긴다.
   직무 이름으로 기술 요구를 추정하거나 전체 공고 분석 완료로 표시하지 않는다.
6. **AS-306** — **Given** 합성 공고에 “운영 경험 3개월 이상 필수. 단, 교육용 실습은 제외”라는 조건이 명시된 경우,
   **When** 구조화하면, **Then** 기간 비교의 값·단위·이상 조건, 필수 구분, 실습 제외 의미를 함께 보존한다.
   이 수치는 합성 원문의 조건이며 제품의 공통 자격 기준으로 확장하지 않는다.
7. **AS-307** — **Given** 채용 요구로 보이는 선택 발췌가 있으나 주체·직무·예외·앞뒤 조건을 판단할 문맥이 부족한 경우,
   **When** 요구를 검토하면, **Then** 참조 가능한 부분과 보완할 문맥을 구분한 후보로 남기고 완전한 명시 요구로 확정하지 않는다.
   미보존 지원자격·우대 항목을 요구 없음으로 처리하거나 특정 직무에 임의 배정하지 않는다.

### User Story 4 - 활용 가능한 범위와 제한을 함께 전달받기 (Priority: P1)

추천 담당자는 KnowledgeBundle에 해당하는 결과를 받아 어느 진술을 근거로 사용할 수 있는지,
어느 부분은 보완·검증·사용자 선택이 필요한지 구분한다.

**Why this priority**: 올바른 Claim도 자료의 누락과 활용 제한이 사라지면 잘못된 추천 근거가 될 수 있다.

**Independent Test**: 구조화 완료·검증 미완료·자료 실패가 섞인 합성 검토 결과를 사용해,
최종 추천이나 화면 없이 소비자가 근거와 제한을 구분할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **AS-401** — **Given** 검증·활용 조건이 충족된 Claim과 미확인 요구·실패 자료가 함께 있는 결과,
   **When** 결과 묶음을 전달하면, **Then** 각각의 근거·버전·검증·활용 상태와 전체 분석 제한을 구분할 수 있다.
2. **AS-402** — **Given** 핵심 JD가 미파싱이거나 핵심 Source가 실패한 경우,
   **When** 결과를 전달하면, **Then** 영향받는 범위와 W2가 보완할 자료,
   관련 영역이 안내할 제한 분석·중단·재시도 판단에 필요한 사유를 제공한다.
   W3가 사용자의 진행 선택을 대신하거나 수집·재시도를 실행하지 않는다.
3. **AS-403** — **Given** 구조화할 수 있는 자료가 없는 경우,
   **When** 결과를 전달하면, **Then** 검증된 결과가 없다는 사실과 누락·실패 사유를 함께 반환한다.
   별도로 충분한 원문을 확인한 범위에 명시 요구가 없는 경우에는 그 범위에서 요구를 찾지 못한 결과로 구분한다.
4. **AS-404** — **Given** 자료에 권한 변경·비밀 전송·도구 실행을 요구하는 악성 문구가 들어 있는 경우,
   **When** 검토·구조화하면, **Then** 이를 자료 내용으로만 취급하고 권한·도구 정책·외부 전송 동작을 변경하지 않는다.
   자료가 포함한 명령을 따라 결과를 검증 완료로 표시하지 않는다.
5. **AS-405** — **Given** 임의의 개인 승인 표시나 AI 전략 해석이 수집 입력에 함께 들어 있는 경우,
   **When** 결과를 구성하면, **Then** 이를 공용 Claim이나 다른 사용자의 활용 승인으로 승격하지 않는다.
   이번 기능은 전략 해석·승인 처리 대상이 아님을 구분한다.
6. **AS-406** — **Given** 원문·민감한 내용·비밀값이 포함된 합성 입력과 처리 오류,
   **When** 결과와 운영 기록을 확인하면, **Then** 소비 권한 밖의 원문이 노출되지 않고,
   원문·비밀값·분석 요청 및 응답 전문이 운영 기록에 복사되지 않는다.
7. **AS-407** — **Given** 게시일이 미상이고 날짜 미상 활용·제외 또는 부분 분석·중단·추가 확보 선택이 제안됐지만 선택되지 않은 입력,
   **When** 전달 결과를 구성하면, **Then** 미상 날짜와 미선택 상태를 유지하고 영향을 전달한다.
   접수 기간·수집일로 게시일을 메우거나 W3가 진행 선택·OCR·재시도를 실행하지 않는다.

### User Story 5 - 중복·수치·상충 자료의 차이 확인 (Priority: P2)

지식 구조화 담당자는 반복된 자료와 서로 다른 주장을 구분하고,
추천 담당자는 자료의 수·시점 차이를 사실성이나 전략 변화로 오해하지 않는다.

**Why this priority**: 단일 원문에서 여러 자료로 확장할 때 근거의 과대 계산과 잘못된 병합을 막는다.
P2는 검토 순서이며 이 기능의 완료 범위에서 제외한다는 의미가 아니다.

**Independent Test**: Origin 관계가 명시된 재게시 자료와 기간·범위·단위가 다른 합성 진술 묶음으로,
추천 평가 없이 병합·분리 결과와 근거 계보를 검증한다.

**Acceptance Scenarios**:

1. **AS-501** — **Given** 같은 발표를 재게시한 관계가 확인된 합성 자료 5개,
   **When** 동일 진술을 정리하면, **Then** 각 문서의 참조를 보존하면서 하나의 Origin에서 온 근거로 구분한다.
   독립 증거 5개나 중요도 상승으로 설명하지 않는다.
2. **AS-502** — **Given** 비슷한 진술이지만 기간·단위·대상 범위·비교 기준이 다른 합성 자료,
   **When** 정리하면, **Then** 차이를 보존하여 별개로 제공하고 수치를 합치거나 의미를 변경하지 않는다.
3. **AS-503** — **Given** 동일 범위·기간·지표에 서로 다른 값을 말하는 합성 자료,
   **When** 검토하면, **Then** 양쪽 주장과 근거를 보존하고 충돌 및 추가 확인 필요를 전달한다.
   한 값을 임의로 정답으로 선택하지 않는다.
4. **AS-504** — **Given** 서로 다른 시기의 공고와 기사, 또는 발행일이 미상인 자료,
   **When** 비교하면, **Then** 확인된 시점·범위를 그대로 제공한다.
   후자가 전자를 대체하거나 기업 전략이 전환되었다고 단정하지 않고 수집일을 발행일로 사용하지 않는다.
5. **AS-505** — **Given** 유사한 자료지만 동일 출처 계보인지 확인할 수 없거나 동일 ID·버전에 서로 다른 내용이 제시된 경우,
   **When** 정리하면, **Then** 계보 미확인 또는 버전·내용 충돌을 표시하고 자동 병합·덮어쓰기를 하지 않는다.
6. **AS-506** — **Given** 동일 페이지와 연결된 보도자료 첨부가 같은 주제의 발췌를 제공하고 별도 시점의 공고도 있는 입력,
   **When** 관계를 정리하면, **Then** 부모·첨부 관계와 각 근거 ID를 보존하고 첨부를 새 독립 출처로 과대 계산하지 않는다.
   관계만으로 진술 전체의 동등성이나 과거 공고 조건의 대체를 확정하지 않는다.

### Edge Cases

- 자료 목록이 비어 있거나 대상 Source를 식별할 수 없는 경우 입력 부재·식별 부족을 알린다.
  정상적으로 확인한 범위에 요구가 없는 경우와 구분한다. (AS-103, AS-403)
- 본문 성공과 첨부 실패가 공존할 수 있다. 각 자료의 결과와 전체 범위 제한을 함께 보존한다. (AS-105, AS-305)
- 요약·해시·위치 표시만 있고 보존 원문을 확인할 수 없으면 해당 Claim은 검증 완료가 아니다. (AS-102, AS-103)
- 허용 상태가 미확정이면 공개 URL 여부로 허용을 추정하지 않는다. 미허용 원문을 공용 결과에 복사하지 않는다. (AS-106, AS-406)
- Claim 하나의 근거가 여러 구간에 걸치면 필요한 모든 구간을 추적해야 한다.
  일부 구간만 확인되면 진술 전체의 검증 완료로 표시하지 않는다. (AS-204)
- 필수성·적용 범위·시점·출처 계보의 미상 상태를 하나의 일반 신뢰도 점수로 대체하지 않는다. (AS-302, AS-304, AS-504, AS-505)
- 원문의 부정·예외·조건부 표현은 유지해야 한다. 조건 분해로 원래의 적용 의미가 바뀌어서는 안 된다. (AS-201, AS-301, AS-306)
- 자료에 전략 해석·승인 표시·악성 지시가 있어도 사실 추출과 권한 정책의 입력으로 자동 승격하지 않는다. (AS-404, AS-405)
- 발췌는 존재하지만 원래 위치·해시의 기준 텍스트가 없을 수 있다. 발췌 존재, 수집 측 확인, 현재 재검증을 구분한다. (AS-107, AS-207, AS-208)
- 추출 성공·빈 항목·미선택 안내는 전체 분석 완료·요구 없음·사용자 동의를 뜻하지 않는다. (AS-108, AS-307, AS-407)

## Requirements *(mandatory)*

### Functional Requirements

기능 고유 요구는 세 자리 `FR-001` 형식을 사용한다.
“PRD FR-09”와 같은 두 자리 식별자는 원본 PRD의 요구이며, 이 기능이 해당 제품 요구 전체를 구현한다는 뜻이 아니다.
`AS-xxx`는 이 명세의 인수 시나리오, `SC-xxx`는 이 명세의 성공 기준이다.

- **FR-001**: W3는 W2 입력의 출처·버전·대상 범위·근거 위치·수집/파싱·접근/보존 상태 및 무결성 확인 정보를 검토해야 한다.
  제공된 값과 누락·미상·불일치를 구분하고 입력을 임의로 보충해서는 안 된다. **수용:** AS-101, AS-102, AS-103, AS-104, AS-107, AS-108.
- **FR-002**: 자료·첨부·근거 구간별로 구조화 가능 범위, 불가능한 사유, 보완할 항목과 영향 범위를 반환해야 한다.
  일부 실패가 다른 자료의 결과를 누락시키거나 전체 성공으로 덮여서는 안 된다. **수용:** AS-105, AS-108, AS-305, AS-307, AS-401, AS-402.
- **FR-003**: 보존된 원문, 일치하는 출처 버전, 근거 위치와 무결성을 확인할 수 없는 범위에는 검증 완료를 표시해서는 안 된다.
  요약·해시·샘플 줄 번호만으로 이 조건을 대체해서는 안 된다. 해시가 있어도 그 대상과 재현 범위를 확인해야 한다.
  **수용:** AS-102, AS-103, AS-104, AS-204, AS-207, AS-208.
- **FR-004**: 접근·보존·공용 활용이 미허용이거나 미확인인 내용은 공용 지식으로 전달하지 않아야 한다.
  필요한 확인과 제한 사유는 원문을 권한 밖에 노출하지 않는 범위에서 제공해야 한다. **수용:** AS-106, AS-406.
- **FR-005**: 근거가 충분한 원문에서 실제 언급된 범위의 Claim을 구조화해야 한다.
  공식 선언·계획·관찰된 실행·결과·채용 요구를 구분하고 원문에 없는 사실이나 AI 해석을 추가해서는 안 된다.
  **수용:** AS-201, AS-202, AS-405.
- **FR-006**: 각 Claim과 명시 Requirement의 원문 발췌·위치·SourceVersion 및 적용 범위를 역추적할 수 있어야 한다.
  링크된 구간이 실제 진술을 뒷받침하는지 확인하고 불일치는 검증 실패로 전달해야 한다.
  보존 발췌 안의 위치와 그 발췌가 온 원문 위치를 혼동해서는 안 된다. **수용:** AS-201, AS-204, AS-207, AS-301, AS-307.
- **FR-007**: 검증 결과는 완료된 검사·미완료 검사·실패 사유와 활용 제한을 구분해야 한다.
  중요한 정보에 필요한 추가 검증이 미완료이면 검증 완료로 표시하지 않아야 한다.
  수집 측 검사 보고와 W3의 현재 검사를 구분한다. 사실에 대한 사용자 인증이나 전략 해석 승인 절차를 새로 제공하지 않는다.
  **수용:** AS-107, AS-205, AS-208, AS-401, AS-405.
- **FR-008**: Requirement는 공고·기업·조직·직무·시점·원문 기원과 명시된 필수·우대·일반 구분을 보존해야 한다.
  필수성이 불명확하면 일반 요구로 두고 특정 범위를 전체 기업 요구로 확대해서는 안 된다. **수용:** AS-302, AS-304, AS-307.
- **FR-009**: AND/OR, 부정·예외, 비교 조건, 동일 경험에서 충족해야 하는 결합관계를 원문 의미대로 보존해야 한다.
  조건을 분해해 원래의 조건부 의미를 없애거나 서로 다른 활동으로 충족했다고 판단해서는 안 된다. **수용:** AS-301, AS-306.
- **FR-010**: 기술의 원래 표현을 보존하고 명확한 동의어만 연결해야 한다.
  다른 기술의 병합, 미파싱 자료의 기술 추정, 원문에 없는 역량·기술·요구 생성은 금지한다. **수용:** AS-202, AS-303, AS-305.
- **FR-011**: 진술의 수치·단위·기간·대상 범위·비교 기준과 발행일·수집일·유효시점을 구분해야 한다.
  미상 정보를 임의의 값·현재 시점으로 보충하거나 서로 다른 지표의 의미를 바꾸어서는 안 된다. **수용:** AS-407, AS-502, AS-504.
- **FR-012**: 명확히 동일한 Claim만 병합하고 모든 원문 참조와 확인된 재게시·인용 계보를 보존해야 한다.
  계보 미확인 자료를 자동 병합하거나 반복을 독립 증거·중요도로 과대 계산해서는 안 된다. **수용:** AS-501, AS-505, AS-506.
- **FR-013**: 범위·기간·의미가 다르면 진술을 별개로 유지해야 한다.
  상충 근거는 양쪽 참조·차이·추가 확인 필요와 함께 전달하며,
  임의의 정답 선택·역사 삭제·전략 변화 판정을 해서는 안 된다. **수용:** AS-502, AS-503, AS-504, AS-505.
- **FR-014**: KnowledgeBundle에 해당하는 결과는 구조화 내용, 입력·결과 버전, 근거 참조,
  적용 범위·시점, 검증·활용 상태, 충돌·누락·부분 실패와 분석 제한을 포함해야 한다.
  소비자는 검증된 내용과 미확인 내용을 구분할 수 있어야 한다. **수용:** AS-107, AS-108, AS-208, AS-401, AS-402, AS-407.
- **FR-015**: 핵심 근거의 부족 여부·영향과 보완할 자료를 제공해야 한다.
  W1/W4가 안내할 제한 분석·중단·재시도 선택을 W3가 대신하거나 수집·재시도를 실행해서는 안 된다. **수용:** AS-402, AS-407.
- **FR-016**: 검증된 결과가 없으면 입력 부재, 근거 부족, 처리 실패,
  충분히 확인한 범위에서 명시 요구를 찾지 못한 경우를 구분해야 한다.
  미수집·미파싱·의도적 미보존을 사실·요구사항의 부재 또는 지원 불가로 표현해서는 안 된다. **수용:** AS-102, AS-108, AS-305, AS-307, AS-403.
- **FR-017**: 외부 문서의 명령·개인 승인 표시·AI 해석이 권한·도구 정책 또는 공용 사실을 변경하지 못하게 해야 한다.
  수집 입력은 개인 승인 처리나 자유로운 명령 실행의 경로가 아니다. **수용:** AS-404, AS-405.
- **FR-018**: 입력 원문과 기존 버전 참조를 변경하지 않고 결과에서 사용한 입력·근거 버전을 식별할 수 있어야 한다.
  같은 식별자에 다른 내용이 제시되면 불일치로 전달해야 한다. 후속 저장·검색·삭제 시스템을 이 기능에서 구현하지 않는다.
  **수용:** AS-107, AS-206, AS-207, AS-505.
- **FR-019**: 결과는 허용된 소비 범위에서만 제공하고 개인·비공개 내용의 공용 전파를 막아야 한다.
  운영 기록에 원문, 비밀값, 분석 요청·응답 전문을 복사해서는 안 된다. 인증 기능의 신설은 범위 밖이다.
  **수용:** AS-106, AS-406.
- **FR-020**: 정상 인수 검증에는 기대 Claim·Requirement가 명시된 합성 사례를 사용하고,
  기존 요약 샘플·새 PM 관측 패키지의 제한 사례와 구분해야 한다. 합성 자료를 실제 기업 자료나 운영 검증 결과로 보고해서는 안 된다.
  실제 패키지의 원문·첨부·분석 내용은 공개 fixture에 복사하지 않는다. **수용:** AS-101, AS-102, AS-107, AS-201, AS-301, AS-501.
- **FR-021**: 원 URL 접근 불가와 보존 근거의 존재를 구분해야 한다.

## Assumptions

### 범위와 책임

- 입력은 W2가 이미 수집·파싱하여 전달한 자료다. 원문이 포함되거나 허용된 보존 원문 참조를 확인할 수 있는 경우를 다룬다.
  미확보 자료의 재수집·첨부 다운로드·PDF 파서는 W2의 후속 작업이다.
- 직접 사용자는 W2·W3·W4 담당자다. 명세의 “확인·전달”은 필요한 결과를 소비할 수 있다는 뜻이며 관리 화면을 요구하지 않는다.
- 현재 단계는 공용 기업지식의 구조화다. 개인 자료를 이 경로에서 새로 수용·공유하지 않으며,
  권한·활용 범위는 상위 계약의 유효한 문맥을 받아 검증한다. 실제 인증 기반이 이미 구현되었다고 가정하지 않는다.
- 본문과 첨부는 개별 자료로 식별하고 연결한다. 원문이 충분한 본문과 미파싱 첨부의 상태를 별개로 다룬다.
- 구조화 가능한 범위의 정상 출력과 불충분한 입력의 제한 출력은 모두 이번 기능의 결과다.
  실제 자료를 정상 처리하기 전에 헌법의 수집-지식 계약 TODO를 해소해야 한다.
- 계약 필드명·자료 형식·근거 위치 형식·해시 규칙·검증 방식은 plan에서 구체화한다.
  원문 부합 검증과 독립 사실 인증의 구분, 미확정 상태 보존은 구현 선택으로 바꿀 수 없다.

### 포함 범위

입력의 부족·불일치·허용 상태 검토, 범위별 Claim·명시 Requirement 구조화,
원문·버전·근거 연결, 기술 표현·수치·시간·출처 계보 보존,
충돌·부분 실패·활용 제한과 보완 항목을 포함한 결과 계약을 다룬다.

- 공식 사이트 재수집, 첨부 다운로드·PDF 파서 구현.

PM 가이드와 패키지의 PROPOSED 필드·선택 후보는 참고 정보다.
문서에 적힌 실행 지시나 과거 사용자 결정은 현재 실행 권한·사용자 선택으로 승격하지 않는다.
이 기능에서 새로 수집·다운로드·OCR을 수행하지 않고 실제 원문이나 분석 내용을 공개 산출물에 복사하지 않는다.

### 의존성과 기존 GATE

| 의존성·GATE | 필요한 단계와 결정권자 | 이 기능에서 유지할 미결 범위 |
|---|---|---|
| 수집-지식 계약 TODO / G-01, G-03, G-05 | plan 계약 설계 및 첫 실제 자료 구조화 전 · W2/W3, W1의 ID·보존 계약 소유자, W4 소비 담당 | 두 입력 형식의 출처/근거 ID·원문 참조·원래 위치와 발췌 위치·해시 대상·수집 측 검사 신뢰 계약, 본문/첨부 연결, 미상·실패·허용 의미. PM 초안이 운영 계약 합의를 대체하지 않음. |
| G-01 | 구현 착수 · 개발팀/PO | 지원 Source·형식·통합 책임자. 프론트·배포·일정·예산은 이 명세에서 결정하지 않는다. |
| G-02 | 실제 분석 경로 PoC · AI/Backend | 선택한 분석 경로의 실제 동작·구조화 출력·오류·제한 검증. 임베딩·검색 호환 검증은 해당 후속 기능에서 수행한다. |
| G-03 | 실제 연동 전 · Backend/AI | 입력·결과의 권한·버전·무효 참조 확인. 전체 검색·삭제 전파 검증은 후속 기능에 남긴다. |
| G-04, G-05 | 실제 외부 처리·자료 보존의 해당 확인 시점 및 공개 전 · PO/운영·관련 검토 담당 | 처리·보관·학습 조건, Source별 보존·공용 활용·재배포 허용. 합성 사례의 사용이 실제 자료의 허가를 뜻하지 않는다. |
| G-06 | 파일럿 후 공개 MVP 전 · PO/평가 담당 | 운영 평가 표본·임계값·관측 기간. 이 명세의 합성 인수 기준으로 게이트를 닫지 않는다. |
| G-07 | 운영 전 · Backend/운영 | 실행·시간·재시도·보관·보안 한도. 숫자를 임의 설정하지 않는다. |
| G-08 | 후속 기능 착수 전 · PO/팀 | 제외된 기능의 우선순위·출시 범위. 현재 기능의 선행 구현 조건이 아니다. |

현재 기능의 목적·범위·인수조건에 대해 추가 사용자 결정이 필요한 항목은 확인되지 않았다.
명세에서 남긴 계약의 구체화와 기존 GATE는 plan 및 해당 실행 단계에서 다룬다.
GATE를 이미 통과했거나 실제 자료 연동이 완료되었다는 의미로 “명세 준비 완료”를 사용하지 않는다.
