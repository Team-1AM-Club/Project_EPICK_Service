# SK하이닉스 수집 샘플 → 매칭담당 전달안

기준일: 2026-09-07 · 상태: **PROPOSED / MANUAL_REVIEW_DRAFT**

수집담당의 [원본 샘플](skhynix_collection_contract_sample.json)을 기준으로 [Claim 예시 JSON](skhynix_claim_handoff_sample.json)을 작성했다. **Claim 예시는 6개이며, 현재 운영 매칭에 사용 가능한 검증된 Claim과 Requirement는 각각 0개다.** 예시 검토와 원본 보완에 사용할 수 있다. 실제 매칭 입력으로 사용하려면 아래 보완이 필요하다.

## 전달 범위와 ID 연결

원본에는 Source 2개, 요약 구간 9개, 첨부 3개가 있다. `source_id`와 `segment_id`는 있지만 **SourceVersion ID와 Evidence ID는 없다.** 9개 구간 모두 `raw_text_in_sample=null`이고, 본문 2개의 `content_hash`도 null이다. 줄 번호는 수집 도구의 임시 위치이며 보존 원문에서 재현되는 위치인지 확인되지 않았다.

이에 따라 실제 ID는 null로 유지했다. 예시 Claim의 `source_version_id`와 `evidence_ids`에 들어가는 `{{W2_...}}`는 **W2가 제공할 실제 ID의 치환 자리**다. 수집일·문서명·요약의 해시로 버전을 만들거나 `segment_id`를 Evidence ID로 간주하지 않았다. 이 샘플은 운영 계약과 구분되는 `claim-handoff-sample/0.1-draft` 형식이다.

```text
draft-claim-05
  source_version_id → {{W2_SV_NEWS20260730}}
  evidence_ids      → [{{W2_EV_NEWS20260730_EVALUATION}}]
                         │ 같은 SourceVersion에 속해야 함
                         └─ 원본 segment_id:
                            NEWS20260730_evaluation_direction
                            /sources/1/evidence_segments/2
```

JSON의 `reference_bindings`에서 모든 치환 자리와 원본 위치를 확인할 수 있다. JSON Pointer는 제출 파일 내 위치이며, HTML/PDF의 원문 locator가 아니다. W2가 실제 ID·발췌·위치를 제공하면 이를 연결하고 W3가 검증한다. **ID를 채우는 작업만으로 검증 완료가 되지는 않는다.**

## Claim 예시

아래 진술은 제공된 메타데이터·요약을 바탕으로 수동 작성했다. 직접 인용문이나 검증된 회사 사실로 취급하지 않는다. 모든 예시의 `verification_status=PENDING`, `usage_status=RESTRICTED`, `usable_for_matching=false`다. 진술 유형은 기존 초안의 `DECLARATION`을 사용한다. predicate는 예시를 읽기 위한 표현이며 확정 운영 enum을 추가한 것이 아니다.

| Claim | 진술 범위 | 참조할 SourceVersion / Evidence 치환 자리 | 매칭 시 지켜야 할 경계 |
|---|---|---|---|
| draft-claim-01 | R260521 접수 기간 2026-03-10~03-23, 마감 현지 17:00 | `W2_SV_R260521` / `W2_EV_R260521_METADATA` | 접수 기간을 게시일·Claim 유효기간으로 대입하지 않음 |
| draft-claim-02 | R260521 직무 목록에 `IT - IT` 포함 | `W2_SV_R260521` / `W2_EV_R260521_METADATA` | 직무명에서 상세 기술·필수요건·배치 지역을 추정하지 않음 |
| draft-claim-03 | 상세 JD는 첨부 Reference File 참조 안내 | `W2_SV_R260521` / `W2_EV_R260521_JD_POINTER` | 첨부의 실제 내용을 확보한 것으로 보지 않음 |
| draft-claim-04 | 7월 30일 기사가 반나절 심층면접을 변화로 소개 | `W2_SV_NEWS20260730` / `W2_EV_NEWS20260730_CHANGES` | 특정 공고·모든 직무에 적용되는 현행 전형으로 확대하지 않음 |
| draft-claim-05 | 같은 기사가 AI 응용 능력 검증을 평가 방향으로 설명 | `W2_SV_NEWS20260730` / `W2_EV_NEWS20260730_EVALUATION` | AI 프로젝트나 특정 기술을 필수 지원요건으로 만들지 않음 |
| draft-claim-06 | 같은 기사가 학력 제한 폐지를 설명 | `W2_SV_NEWS20260730` / `W2_EV_NEWS20260730_EVALUATION` | 과거 R260521의 학위 조건을 소급 삭제하지 않음 |

05·06은 같은 구간의 서로 다른 진술이다. Claim이 2개라고 독립 출처가 2개가 되지는 않는다. 추후 실제 원문 범위에 맞게 Evidence를 세분화할 수 있다.

R260521 지원자격 요약에는 학사 이상 졸업(예정), 2026년 7~8월 입사 가능, 병역·해외여행 조건이 들어 있다. 원문과 예외·결합 논리를 확인하지 못했으므로 확정 Requirement를 만들지 않고 `unassessed_requirements`에 남겼다. 7월 기사의 학력 제한 폐지와도 범위·시점 확인 없이 병합하거나 모순으로 확정하지 않는다.

## 날짜 미상 처리 확인

| 항목 | 원본 관찰 | 전달·처리 기준 |
|---|---|---|
| 공고 게시일 | `null` + `NOT_EXPOSED_ON_PAGE` | 그대로 보존. 화면은 “게시일 미상” |
| 접수 시작·마감일 | 2026-03-10 / 2026-03-23 | 공고 접수 기간으로만 사용. 게시일을 역산하지 않음 |
| 접수 마감 시각 | `17:00`, 시간대 미제공 | 시간대는 null. 수집 시각의 `+09:00`을 복사하지 않음 |
| 수집 시각 | 2026-09-07T21:27:00+09:00 | 파일이 보고한 수집 시점. 게시일·시행일·최신성 근거로 사용하지 않음 |
| 수집 당시 공고 상태 | `APPLICATION_CLOSED` | 과거 공고로 범위를 제한. 지원자 부적격 판정과 구분 |
| 기사 게시일 | 2026-07-30 + `EXPLICIT_ON_PAGE` | 샘플 제공값 보존. 정책 시행일이나 현재 유효함을 의미하지 않음 |
| 수정일·Claim 유효기간 | 미제공 | null 유지. 접수 기간·게시일로 임의 대입하지 않음 |

날짜 미상 자료는 사용자가 **날짜 미상을 표시하고 활용 / 해당 자료 제외** 중 선택할 수 있도록 W1/W4에 전달한다. 이 작업에서 사용자가 어느 쪽도 선택한 적은 없으므로 `selected=null`이다. 활용 선택은 근거·사용 허용 검증을 면제하지 않는다. 원문이 보완되어도 게시일을 확인하지 못하면 날짜 미상 표시는 계속 유지한다.

## 첨부 누락 처리 확인

현재는 “첨부 파일이 없다”가 아니라 **“첨부 3건을 발견했으나 수집 도구가 콘텐츠 형식을 지원하지 않아 내려받기·본문 확보가 완료되지 않았다”**는 상태다. 3건 모두 `DISCOVERED`, `FETCHER_UNSUPPORTED_CONTENT_TYPE`, `UNPARSED`다. HTTP 상태나 실제 파일의 손상·삭제 여부는 제공되지 않았으므로 404·삭제·손상으로 바꾸지 않는다.

| 첨부 ID | 원본의 필수 여부 | 확인하지 못한 범위 | 전달할 조치 |
|---|---|---|---|
| `R260521_jd_ko_icheon` | true | 한국어 이천 JD의 상세 업무·필수/우대 기술·예외 | 해당 범위의 전체 분석 불가. W2가 파일 확보·형식 확인·파싱 후 근거 제공 |
| `R260521_jd_en_icheon` | false | 영어 JD 내용, 한국어와의 동일성·차이 | 미파싱을 그대로 표시. 자동 필수화나 독립 근거 추가 금지 |
| `R260521_faq_ko` | false | 첨부 FAQ의 추가 조건·예외 | 비필수라도 누락 사실과 관련 판단의 한계를 전달 |

`application/octet-stream`은 수집기가 관찰한 콘텐츠 유형이며 PDF 파일의 부재를 증명하지 않는다. `expected_file_type=application/pdf`도 실제 파일 형식 확인을 대신하지 않는다. 부모 본문이 확보되어도 필수 JD를 읽지 못하면 원본의 `PARTIAL_REQUIRES_ATTACHMENTS`를 유지한다. 파일을 내려받았더라도 파싱이 끝나기 전에는 상세 JD 분석 완료로 바꾸지 않는다.

본문과 첨부는 별도 Source/SourceVersion/Evidence로 연결해야 한다. 원본의 첨부에는 `attachment_id`만 있으므로 새 전역 Source ID를 임의 발급하지 않았다. `parent_source_id`를 보존했고 실제 첨부 ID·버전·근거는 W2/W1 보완 대상으로 남겼다. 이천 JD를 근거로 분당·서울 직무까지 확보되었다고 볼 수도 없다.

기사의 `attachments=[]`는 샘플이 첨부를 열거하지 않았다는 뜻이다. 탐색 범위가 없어 “첨부 없음 확인”으로 표시하지 않는다. 기사에 연결된 `talent.skhynix.com`도 `NOT_FETCHED_IN_THIS_SAMPLE`이므로 개별 모집요강·세부 요건의 근거로 사용하지 않는다.

상세 JD가 필요한 분석에는 **확인된 범위로 제한 분석 / 분석 중단 / 첨부 보완·재시도** 선택을 제공한다. `selected=null`이며, 실제 Job 상태 변경이나 재시도는 수행하지 않았다. 현재 파일은 본문도 원문 검증이 안 되어 있으므로 제한 분석을 선택해도 이 6개 초안을 매칭에 사용할 수 없다. 별도로 문항·사용자 경험이 충분한 경우의 기업 근거 없는 제한 추천은 W4가 판단한다.

## W4 수신·소비 기준

- 이 파일은 계약 검토 자료다. `CONTRACT_SAMPLE_DIAGNOSTIC` 또는 미치환 `{{...}}` 참조가 있는 결과는 운영 매칭 입력으로 거부한다.
- 사용할 Claim의 `source_version_id`가 실제 버전으로 해소되고, 모든 `evidence_ids`가 그 버전에 속하는지 검사한다. URL이나 부모 본문 ID로 첨부 근거를 대신하지 않는다.
- W3의 필요한 검증이 완료되고 현재 사용이 허용된 범위만 소비한다. 본문 수집 `SUCCESS`와 사용자 활용 선택을 W3 검증 완료로 복사하지 않는다.
- 빈 `claims` / `explicit_requirements`와 `NOT_ASSESSED`는 “확인 못함”이다. “요구 없음”, “미충족”, “지원 불가”로 해석하지 않는다. 확인 가능한 다른 범위까지 일괄 미충족으로 처리하지 않는다.
- 검증된 기업 Claim을 받더라도 문항 요구가 우선이다. 실제 사용자 Episode·문항·지원 프로젝트·Snapshot 없이 추천·자격 충족을 판정하지 않는다.
- 과거 공고와 후속 기사의 범위·시점을 보존한다. 이전 Snapshot을 조용히 덮어쓰거나 뉴스의 평가 방향을 개별 공고 필수요건으로 전환하지 않는다.

`null`은 옆 상태·이유와 함께 해석한다. 빈 배열은 이 결과에 포함할 항목이 없다는 뜻이며 세상에 존재하지 않음을 증명하지 않는다. 예시 스키마에 정의된 진단 필드를 누락해 한계를 숨기지 않는다. 실제 API의 필수 필드·enum·버전 협상은 공동 계약으로 확정한다.

## 수집담당 보완 요청과 다음 전달 순서

1. **W2/W1:** 본문 2건과 첨부별 실제 Source/SourceVersion ID, 버전 식별·변경 기준, 부모·첨부 관계를 제공한다.
2. **W2:** 9개 요약 구간에 대응하는 허용된 최소 원문 발췌, 앞뒤 조건·예외, 실제 Evidence ID, 보존 참조와 재현 가능한 위치를 제공한다. 해시는 대상·정규화·인코딩을 함께 명시한다. 전문 전체 저장을 일률적으로 요구하지 않는다.
3. **W2:** 한국어 JD를 우선 보완하고, 영어 JD·FAQ의 미파싱 결과도 유지한다. 관련 채용 사이트의 개별 공고는 필요 범위가 정해지면 별도로 수집·연결한다.
4. **W1/W2:** 보존·사용 허용 상태와 날짜 미상 정보를 제공한다. 게시일을 확인할 수 없으면 사유를 유지한다.
5. **W3:** 실제 ID로 연결한 새 결과에서 원문 일치·의미·범위·시점·무결성 및 필요한 추가 검증을 수행한다. 조건 문장은 원문 논리를 보존한 Requirement로 별도 구조화한다.
6. **W4/W1:** 검증된 사용 가능 범위와 잔여 한계를 소비하고 필요한 사용자 선택을 받는다. `selected=null`을 자동 승인으로 처리하지 않는다.

근거 규칙은 [기존 수집 샘플 어댑터](../specs/001-source-knowledge-validation/contracts/collection-sample-adapter.md), [구조화 계약 §4·6·7](../specs/001-source-knowledge-validation/contracts/structure-contract.md), [PRD](../Docs/PRD_AGENT.md)의 FR-09~13 및 AT-12/13을 따른다. 기존 계약·원본 샘플은 변경하지 않았다. 새 API·Job enum·운영 스키마도 도입하지 않았다.

## 검증 범위

2026-09-07 Node.js의 JSON 파서와 `node:assert/strict`로 **9개 점검 그룹을 통과**했다.

- JSON 문법과 진단 모드·운영 사용 차단 표시
- Source 2개의 원본 ID·날짜·수집 상태 보존
- 요약 구간 9개의 입력 위치·줄 번호 매핑, 실제 Evidence ID·인용문 null 유지
- 첨부 3개의 부모 연결·다운로드/파싱 상태·필수 여부 보존
- Claim 6개의 모든 참조 해소, Evidence와 SourceVersion의 소속 일치
- 게시일 미상·접수 기간·수집일·미확인 시간대 분리
- Requirement 미평가, 사용자 선택 null, 운영 사용 목록 0개 유지
- 뉴스의 첨부 탐색 범위 미상·미수집 관련 링크 상태 보존
- 전달 문서의 모든 로컬 링크 해소

이는 작성한 파일의 구조·원본 대응에 대한 검사다. 웹 원문 재수집·첨부 다운로드·진술의 의미 검증·실제 W4 연동은 수행하지 않았다. 원본 수집 샘플은 수정하지 않았다.
