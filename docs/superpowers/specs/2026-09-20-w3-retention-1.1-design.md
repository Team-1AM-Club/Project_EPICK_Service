# W3 Retention 1.1 Design

Status: approved by PM on 2026-09-20 at `2026-09-20T08:33:43Z`.

## Scope

Apply `w3.retention/1.1` to the existing W3 Core Decision runtime without changing the
adopted W3→W1 event wire. Record the inputs still required for the real analysis caller,
Authority, deletion dispatcher, source registry, image, IAM/SQS, scheduler, and joint CT12.

## Policy

- Private event/request bodies have an absolute deadline of `created_at + 2,592,000` seconds.
- A `TRANSPORT_HANDOFF` body expires at the earlier of the absolute deadline and
  `last_successful_published_at + 1,209,600` seconds.
- `PENDING`, `RETRY`, and `HELD` expire at the absolute deadline as `DELIVERY_EXPIRED`.
- The first terminal deadline is immutable. Terminal metadata expires after 7,776,000 seconds.
- An owner tombstone expires 31,536,000 seconds after the first valid deletion. Repeated deletion
  never moves `deleted_at`.
- A Company/Source revision counter expires 7,776,000 seconds after an authoritative permanent
  retirement. A persistent retired-source marker continues to reject the retired identifier.
- A supported redacted/quarantined backup expires after at most 2,592,000 seconds and never later
  than the earliest deletion deadline of metadata included in the backup.
- All comparisons use UTC epoch seconds and expire when `now >= expires_at`.
- Replay may update the last successful handoff time but cannot change `created_at` or extend the
  absolute body deadline.
- Valid owner deletion overrides every body deadline and purges the body in the deletion transaction.

## Enforcement

Every supply, relay, and replay transaction evaluates body deadlines before reading or sending a
body. Expired bodies are unavailable even if the five-minute scheduler has not run. Purge records
the logical deadline as `terminal_at`, not the later sweep time. Startup and scheduled `expire`
perform body, terminal metadata, tombstone, and retired-counter cleanup and report counts without
payloads.

`AnalysisPlan` carries a trusted analysis request identifier and issue time. W3 rejects future or
older-than-30-day requests. The real caller and Authority must bind the identifier, issue time,
content, owner, job/source context, and current state in authoritative storage. The adapter remains
pending until W1 supplies its code path, authentication, timeout, and error contract.

## Migration

Add lifecycle columns without replacing the SQLite database. For an existing row, derive
`created_at` only from a parseable stored event `occurred_at`. A row without a trustworthy basis is
blocked from live send and its body is removed; migration does not give it a new retention window.
Unknown legacy tombstone dates remain visible as migration blockers and are not assigned a fresh
365-day period.

## Operational boundary

W1 owns the five-minute scheduler, 15-minute database deletion SLO, 24-hour log/backup object
deletion SLO, immutable image, persistent volume, IAM/SQS, monitoring, and deployment. W3 owns the
runtime enforcement, metadata-safe evidence, adapter boundary, and joint CT12 participation.
Synthetic adapters prove only local behavior.
