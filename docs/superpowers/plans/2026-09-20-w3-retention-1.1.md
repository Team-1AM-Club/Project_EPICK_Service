# W3 Retention 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce the approved W3 body, metadata, tombstone, counter, and backup deadlines locally and publish an exact checklist for the real W1/app connection inputs.

**Architecture:** Keep the adopted event wire unchanged. Put immutable policy values and deadline calculations in a focused retention module, migrate the existing SQLite tables in place, and enforce deadlines inside the current CoreRuntime transactions before any body use. Keep unavailable W1/app adapters as explicit readiness blockers.

**Tech Stack:** Python 3.12, SQLite, Pydantic 2, pytest 9, Ruff

**Spec:** `docs/superpowers/specs/2026-09-20-w3-retention-1.1-design.md`

## Global Constraints

- Policy revision is exactly `w3.retention/1.1`.
- Body windows are 1,209,600 and 2,592,000 seconds; metadata, tombstone, and retired-counter windows are 7,776,000, 31,536,000, and 7,776,000 seconds.
- Boundary comparison is `now >= expires_at`.
- Replay never changes `created_at`; duplicate terminal/delete operations never move their first timestamps.
- No event/request body, owner ID, credential, exception text, or secret is exposed in inspect/evidence.
- No actual endpoint, role, queue, registry, deployment, or CT12 success is invented.

## Review Focus

- Rows exactly on a deadline must be blocked before send and purged.
- A day-29 handoff must still expire on the day-30 absolute deadline.
- Retry, HELD, replay, and repeated deletion must not move immutable lifecycle timestamps.
- Legacy rows without trustworthy timestamps must never enter live transport.
- Cleanup of idempotency metadata, tombstones, and counters must not permit stale request, deleted owner, or retired Source reuse when authoritative adapters reject them.
