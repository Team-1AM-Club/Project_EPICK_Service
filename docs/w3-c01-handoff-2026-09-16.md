## C-01 입력과 순번

- envelope `schema_version=1.0`, `producer=w2`, `aggregate_type=source`만 받는다.
- `source.version.available`, `source.observation.changed`, `source.restriction.changed`
  각각 올바른 payload 분기를 검증한다. private `job_id` 및 payload 안 transport 필드는 거절한다.
- 원본 W2 입력 DTO와 수신 SHA256 계산에는 원래 값을 유지한다. 내부 UUID 비교/저장 키는
  소문자 canonical 값으로 통일한다. UUID 대소문자로 Source가 분리되거나 제한을 피할 수 없다.
- `static_html`, accuracy 4종, `replacement_ref`를 다른 의미의 값으로 바꾸지 않는다.
  replacement_ref는 자동 재지정 명령으로 실행하지 않는다.
- 날짜 unknown, partial, limitations를 보존한다. 날짜 추정이나 누락 섹션 생성은 하지 않는다.
- 수신 이력에는 canonical JSON의 SHA256 및 본문을 제거한 projection을 저장한다.
  원본 event JSON을 영구 보관하는 archive 기능은 아니다.

| 필드 | 후보 의미 |
|---|---|
| `event_cursor` | 해당 Source에서 연속 적용한 전체 이벤트 순번 |
| `required_event_cursor` | 수신/복구 과정에서 확인한 최대 전체 순번; 낮은 replay watermark로 줄이지 않음 |
| `restriction_revision` | 연속 적용한 제한 변경 순번; version/observation 수신으로 증가하지 않음 |
| `required_restriction_revision` | 수신한 restriction의 최대 순번 |
| `generation` | W3 사용 가능 상태/색인 변경 번호; W4 캐시 무효화에 사용 |

원본 4개를 순서대로 받으면 **event_cursor=4, restriction_revision=1**이다.
restriction 순번을 Source 단위 연속 번호로 정의한 것은 W3 후보 규칙이다. W2가
restriction_id 단위 번호를 사용한다면 채택 전에 계약과 구현을 조정해야 한다.

gap에서는 `EVENT_GAP` 또는 `RESTRICTION_GAP`으로 차단한다. 중복 event ID+동일 원본은
`DUPLICATE`; 동일 ID/transport 순번의 다른 원본 및 제한 순번 재사용은 `CONFLICT`다.
COMMITTED는 수신 내역을 트랜잭션에 반영했다는 뜻이며 사용 가능하다는 뜻이 아니다.
snapshot 이전의 아직 알려지지 않은 오래된 event는 `STALE`로 처리한다.

## 제한 범위와 색인

실행 시 `--restriction-scope source|version`을 반드시 지정한다. 기본값은 없다.

- `source`: 모든 active 제한이 해당 Source 사용을 차단한다. 버전 ID는 근거 참조로 보존한다.
- `version`: 선택된 SourceVersion과 일치하는 active 제한만 적용한다. null 버전은 Source 전체로 해석한다.
- 이 두 해석 및 null 의미는 **공동 확인 필요**하다. 값 변경 시 동일 DB 재사용은 거절한다.
- restriction_id별 상태를 유지한다. 하나의 cleared로 다른 active를 해제하지 않는다.
- error_confirmed/superseded는 보수적으로 차단한다. cleared만으로 accuracy 문제를 제거하지 않는다.
- 최신 version 이벤트가 선택한 정확한 SourceVersion/extraction/representation/normalization 조합을
  IndexKey로 사용한다. 과거 버전 제한을 최신 버전에 붙이거나 추출 ID를 추정하지 않는다.
- 최신 version보다 뒤에 발생한 unavailable/denied observation은 사용을 차단한다.
  후속 available version 또는 정상 observation으로 상태가 바뀌어도 재색인은 필수다.
- version/observation/restriction 적용, gap, 충돌, snapshot마다 기존 색인을 제거한다.
- 색인 요청은 두 순번과 완전한 IndexKey가 현재 상태와 일치해야 한다.
  Evidence ID와 전달된 발췌 SHA256도 producer version의 Evidence와 같아야 한다.
  색인 완료가 Claim의 의미 검증 완료를 뜻하지는 않는다.

## replay / snapshot

`replay.schema.json`의 핵심은 `after_cursor`, `high_watermark`, `retention_floor_cursor`다.
`retention_floor_cursor=N`은 N 이후 이벤트를 복구할 수 있다는 producer 선언이다.
현재 cursor가 N보다 작으면 `SNAPSHOT_REQUIRED`로 차단한다. W2 envelope에 outbox 게시 시간이
없으므로 콘텐츠 게시 날짜를 replay 보관 기준으로 사용하지 않는다.

- 페이지당 500건 이하, 같은 Source, transport 순번 오름차순/중복 없음.
- cursor보다 앞선 `after_cursor` 재시도는 허용, cursor보다 뒤면 `CURSOR_AHEAD`.
- 페이지가 끝나도 확인한 watermark까지 못 채웠으면 `INCOMPLETE`로 계속 차단한다.
- 한 batch는 BEGIN IMMEDIATE 단일 트랜잭션. SQL 오류면 receipt/cursor/outbox 함께 rollback.
- replay는 conflict를 자동 해제하지 않는다.

snapshot은 동일 Source의 원자적 전체 상태다. `complete=true`는 producer가 책임지는 선언이다.
`event_cursor`, `restriction_revision`, SourceVersion별 최신 version event,
restriction_id별 최신 restriction event(해제된 항목 포함), 최신 observation을 함께 보낸다.
이번 후보는 버전/제한 목록 각각 최대 500개이며 더 큰 Source의 분할 snapshot은 미지원이다.

- 알려진 최대 transport/restriction 순번보다 낮으면 `STALE_SNAPSHOT`.
- 기존 상태뿐 아니라 gap 대기 이벤트와도 대조한다. 이미 아는 제한/버전/observation 누락,
  immutable event 변경, restriction 순번 재사용·역전은 `CONFLICT`.
- snapshot에만 포함된 event ID/hash도 영속화하여 후속 ID 재사용을 탐지한다.
- 같은 cursor의 다른 snapshot 원본은 충돌 처리한다. 재전송은 동일 body를 사용한다.
- 성공해도 `history_complete=false`, 색인 ACK false. 정책과 제한 상태가 허용해야 재색인 가능.
- 메타데이터 복구 성공과 사용 복구 성공은 구분한다. **두 순번 gap 없음 + conflict 없음 +
  정책/제한 허용 + 정확한 키 재색인 성공**이어야 READY다.
- 모순된 immutable 이력 자체를 수정해야 하는 경우 강제 덮어쓰기 API는 제공하지 않는다.
  producer 원인 정리와 별도 운영 복구가 필요하다.

## 보관 정책 / W4 ACK

이번 후보는 **허용된 Evidence 발췌만** 색인한다. normalized body의 다운로드/저장은 미지원이다.
official verified, public, collection/excerpt storage/redistribution 모두 allowed일 때만 사용한다.
unknown/denied를 allowed로 해석하지 않는다. 따라서 원본 version 예제의 redistribution=unknown은
색인 ACK를 받을 수 없다. 정상 색인 테스트는 별도 `version-policy-allowed.json` 합성 자료를 쓴다.

TTL 상한 `--max-ttl-seconds`는 필수이며 3600초 예시는 **테스트 설정**이다. 운영값을 정한 것이 아니다.
operator의 expires_at이 현재보다 미래이며 이 상한 이내여야 한다. 조회/status/signals/purge 시
만료된 live index와 documents 행을 제거한다. 유휴 서버의 주기 purge는 운영 scheduler가 호출해야 한다.
메타데이터/해시/receipt/outbox는 후보 DB에서 자동 만료하지 않는다. SQLite 빈 페이지·WAL·백업의
물리적 삭제와 감사 기록 보관 기간은 운영 합의가 필요하다.

| ACK/신호 | 정확한 의미 |
|---|---|
| `receipt=COMMITTED` | 수신 처리 트랜잭션 완료. 제한/gap 상태도 포함 가능 |
| `index_ack=true`, reason READY | 현재 두 순번과 키/정책/TTL에 맞는 색인 준비 완료 |
| W4 delivery `{delivered:true}` | 해당 signal을 참조 W4 어댑터가 영속 반영한 후 ACK |
| C01 signal의 required 값 | `required_event_cursor`, `required_restriction_revision`을 각각 사용 |

혼동을 피하기 위해 C01 signal에는 legacy의 단일 `required_revision` 필드를 넣지 않았다.
W4는 새 DTO를 채택해야 한다. generation 증가 시 캐시 삭제, 동 generation 다른 signal은 충돌,
낮은 generation은 stale. 캐시 조회 시 W3 최신 status를 확인하며 실패하면 반환하지 않는다.
참조 어댑터는 Source당 단일 캐시와 단일 논리 consumer group이다. 여러 Source를 합친 실제
추천 캐시의 의존성 추적 및 W1 authorization/deletion 처리는 호스트 서비스에 연결해야 한다.
DB 교체/초기화 시 이전 W4 캐시 전량 무효화 및 전체 재동기화가 필수다. stream epoch 자동화는 미지원이다.

## 실행 / 연동 지점

```powershell
uv sync --locked
uv run --locked python scripts/export_c01_contract.py --check
uv run --locked pytest -q
uv run --locked python scripts/c01_smoke.py
```

HTTP 서버는 localhost 전용이다. `W3_W2_TOKEN`, `W3_OPERATOR_TOKEN`, `W3_W4_TOKEN`을
서로 다른 값으로 환경에 설정하고 새 DB 경로를 사용한다. `.env` 자동 로드는 하지 않는다.

```powershell
uv run --locked python -m w3_knowledge.c01.http --db .runtime/c01.sqlite --restriction-scope source --max-ttl-seconds 3600
```

| 경로 | 권한 |
|---|---|
| POST `/c01/v1/events`, `/replay`, `/snapshot` | W2 |
| POST `/c01/v1/index`, `/purge` | operator |
| GET `/c01/v1/status/{source_id}` | W2/operator/W4 |
| GET `/c01/v1/search?q=...`, `/signals` | operator/W4 |
| POST `/c01/v1/signals/ack` | W4 |

422 구조/의미 입력 오류, 409 conflict/stale snapshot/cursor ahead, 503 저장소/색인 오류.
성공 HTTP 200에서도 receipt·outcome·reason·index_ack를 각각 확인해야 한다.
TLS, broker, 재시도/DLQ worker, 실서비스 인증·호스팅은 포함하지 않는다.

기존 W3 서비스는 `w3_knowledge.c01.guard.structure_guarded(request, ports, store, keys)`를
명시적으로 호출한다. UUID SourceRef를 지원하고 허용된 live index 발췌만 지식 처리에 통과시킨다.
처리 중 generation이 바뀌면 결과 반환을 보류한다. 기존 policy/semantic 검증은 계속 적용한다.

## 공동 확인표

| 담당 | 결정/연동 필요 사항 |
|---|---|
| W2/W3 | 전체 Source event 연속 순번, Source 단위 restriction 순번 채택 여부 |
| W2/W3 | source/version 제한 적용 범위와 null 의미, cleared accuracy 규칙 |
| W2/W3 | replay floor cursor 및 전체 상태 snapshot의 생산·보관 책임 |
| W3/W4 | IndexKey, static_html, 새 signal DTO와 두 required 필드, generation 캐시 연동 |
| W3/W4/PM | 운영 TTL, 본문 저장 필요 여부, redistribution unknown 처리, 감사/물리 삭제 정책 |
| W1 | retry private endpoint, core decision private 계약, 개인 삭제 신호/epoch/fence 범위 |

W1 항목을 이 구현으로 확정하거나 완료했다고 간주하지 않는다.
